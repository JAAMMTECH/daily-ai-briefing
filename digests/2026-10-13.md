## AI

### Janas: Run LLMs larger than RAM by streaming experts from SSD

Hacker News

Janas-LLM, a C engine, streams the needed mixture-of-experts weights from an NVMe SSD and caches frequently used ones in memory. On a 32 GB laptop with an integrated Intel Arc GPU it reports 37 tok/s on Qwen3-Next-80B (48 GB) versus 2.8 for llama.cpp, though the author calls it an experiment tested on one machine.

Why it's worth knowing: It shows that models larger than RAM can be usable on ordinary hardware, though results on other CPUs, GPUs and disks are untested.

Terms:
- **Janas-LLM** — Project name, not an acronym — An LLM inference engine written in C with no dependencies beyond the C library. It targets mixture-of-experts models on ordinary computers.
- **mixture-of-experts** — Model architecture (often abbreviated MoE) — A model made of many expert sub-networks where only a few activate per token. This means only a fraction of the weights are needed for each step, which is what makes streaming them from disk feasible.
- **NVMe** — Non-Volatile Memory Express — A fast interface protocol for SSDs over PCIe. Drives reach several GB/s reads, far faster than older SATA disks.
- **llama.cpp** — Project name, not an acronym. The .cpp means it is written in C++ — A widely used open-source engine for running quantized LLMs locally on CPUs and GPUs.
- **tok/s** — Tokens per second — Speed measure for text generation. A token is a word fragment the model reads or writes.

https://github.com/prabanta-dev/janas

### AI models can provably hide arbitrary capabilities

Hacker News

Researchers show backdoors that embed encrypted neural networks inside a model's weights, decrypted only on a secret trigger. Under cryptographic assumptions the hidden circuit is hard to find even with full weight access, and it resisted fine-tuning and weight noising in tests on a small chemistry task.

Why it's worth knowing: It suggests behavioral safety evaluations cannot guarantee a model has no hidden dangerous capability. Commenters argued this strengthens the case for trusting the publisher, while noting open weights can at least be scrutinized.

https://arxiv.org/abs/2610.13928

### SonicBoom – llama.cpp's own kernels, 14% faster decode via a graph compiler

Hacker News (watchlist)

SonicBoom, a new C++/CUDA runtime, reports 14% faster decode than llama.cpp on a laptop RTX 3050 using the same quantized kernels, with gains from a graph planner and MLIR compiler. It is v0.0.1, verified on one model, and prefill is about half as fast as llama.cpp.

Terms:
- **MLIR** — Multi-Level Intermediate Representation — A compiler framework from the LLVM project for building optimizing compilers for tensor computations.
- **CUDA** — Compute Unified Device Architecture — NVIDIA's platform for programming GPUs.
- **prefill** — Prompt-processing phase of LLM inference — The stage where the model reads the whole prompt before generating output. It is distinct from decode, which generates tokens one at a time.

https://github.com/hardenedlinux/sonicboom

### Benchmarked Strata 0.1.25 and 0.1.39 against llama.cpp on three cards: an RTX PRO 6000 (96 GB), a 3090 Ti and a 5090 laptop

r/LocalLLM

A benchmark of the Strata engine against llama.cpp on Qwen3.8-Flash-Next (IQ3_S), a model too big for a 24 GB card. Strata produced the first word about 9-10 times sooner on a 3090 Ti and 5090 laptop, and about twice the writing speed on an RTX PRO 6000, where the authors attribute the lead to a draft head llama.cpp did not run.

Why it's worth knowing: The authors' own caveat means the headline speedup on the big card is not like for like.

Terms:
- **Strata** — Project name, not an acronym — An alternative local LLM inference engine compared against llama.cpp here.
- **draft head** — Speculative-decoding component — A small extra predictor that proposes several tokens ahead so the main model can verify them in one pass, speeding up generation.

https://www.reddit.com/r/LocalLLM/comments/1x46wxm/benchmarked_strata_0125_and_0139_against_llamacpp/

### Intel D270 GPU AI Accelerator–Up to 480 GB LPDDR5X

Hacker News

Intel's D270 accelerator pairs 160 GB of LPDDR5X (up to 480 GB from partners) with 1.5 TB/s bandwidth, up to 1.3 PFLOPS FP8, PCIe 5.0 and a 350 W passive-cooled design. Commenters doubt pricing and performance because LPDDR5X is slower than HBM.

Why it's worth knowing: Very large memory on one card could make running big models locally or on-premises cheaper, if bandwidth holds up.

Terms:
- **LPDDR5X** — Low-Power Double Data Rate 5X — A power-efficient memory type used in laptops and phones. It is cheaper and denser than HBM but has lower bandwidth.
- **HBM** — High Bandwidth Memory — Stacked memory placed next to the processor, used in top-end AI accelerators for very high bandwidth.
- **FP8** — 8-bit floating point — A compact number format that speeds up AI math and reduces memory use.

https://www.intel.com/content/www/us/en/products/details/discrete-gpus/data-center-gpu/d-series.html
