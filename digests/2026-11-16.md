### GPU-Initiated DMA Copy Engines in RCCL and RocSHMEM

Hacker News (watchlist)

AMD's ROCm blog describes GPU-initiated SDMA copy engines in RCCL and rocSHMEM. On eight MI350X GPUs, large-message AlltoAll and AllGather bandwidth matches or beats the default path while using one compute unit instead of 64, and rocSHMEM puts of 512 KiB and larger peak with one compute unit and one wavefront.

Why it's worth knowing: During inference, communication sits on the critical path. Letting a DMA engine move the bytes leaves the compute units free for the model.

Terms:
- **SDMA** — System DMA — Dedicated copy engines on AMD GPUs that move data without using the compute units that run the model.
- **RCCL** — ROCm Collective Communication Library — AMD's library for multi-GPU collectives such as AlltoAll and AllGather.

https://rocm.blogs.amd.com/software-tools-optimization/gpu-initiated-sdma/README.html

### llama.cpp was copying 643 MB to the CPU per request. Disabling state saving nearly doubled throughput

r/LocalLLM

A LocalLLM post measured llama.cpp copying about 643 MB from the GPU to the host on every request while serving Qwen3.8-27B to 16 clients on an H100, at 58 tokens per second, nearly two seconds to the first token, and about 35% GPU use. Disabling state saving nearly doubled throughput, because this hybrid model snapshots recurrent state along with the attention cache.

Why it's worth knowing: Low GPU use can mean the server is busy copying checkpoints to the CPU. On hybrid models, state saving is an early place to look.

### ggml-org/llama.cpp b12435

GitHub: ggml-org/llama.cpp

llama.cpp build b12435 makes Vulkan's radix top-k deterministic when many tokens tie. Each subgroup keeps a fixed slice of the row, and overflowing ties are ranked in column order so the lowest columns win, matching CUDA and Metal.

Why it's worth knowing: If ties depend on which thread finishes first, the same prompt can pick different tokens on different runs. A stable rule makes Vulkan comparable with the other backends.

https://github.com/ggml-org/llama.cpp/releases/tag/b12435

### MMFlash: Faster Speculative Decoding for Vision-Language Models

Hugging Face papers

MMFlash adjusts speculative decoding for vision-language models by giving more weight to tokens the drafter misses when the next word depends on the image. Acceptance falls from 46% in the least visual quartile to 22% in the most, and the paper reports lossless speedups up to 3.58x, beating EAGLE-3 by up to 195.4% and DFlash by up to 17.1%.

Why it's worth knowing: A text drafter wastes guesses on tokens that are really about the picture. Training those cases harder is what makes the speedup show up on multimodal models.

https://huggingface.co/papers/2611.18482

### V-JEPA-LM: Video-Language Models That Read Dynamics Beyond Static, Text-Aligned Representations

Hugging Face papers

V-JEPA-LM says video-language models often ignore motion their encoders already measured: a linear probe reads speed from frozen V-JEPA features at 87%, while the language model answers at chance. The authors train on public clips edited so the answer depends only on the change, using 4.53 million samples and 32 visual tokens per frame for models from 1B to 8B.

Why it's worth knowing: A model can name what is in a frame and still miss speed, order, and state. Questions about what changed need training examples where that change is the only difference.

Terms:
- **V-JEPA** — Video Joint Embedding Predictive Architecture — A video encoder trained to predict how a scene changes, rather than to match a caption.

https://huggingface.co/papers/2611.17831

### VibePrevisBench: Evaluating Agentic Coding for 4D Scene Generation in Blender

Hugging Face papers

VibePrevisBench scores coding agents that turn a brief into a Blender 4D scene and a graybox proxy video, across 242 tasks drawn from scripts, photos, continuations, and reference videos. A rule check compares the scene file with hidden facts, and a vision-language judge checks whether those facts are visible; the authors find that reading space and camera motion is what separates the agents.

Why it's worth knowing: The grade covers the scene file a production team would open, including layout and camera, along with the preview video.

https://huggingface.co/papers/2611.15789

### MIRIX-2.0: Multi-Agent Memory System

Hugging Face papers

MIRIX-2.0 keeps full agent memory in six typed stores and searches it under a fixed budget instead of rereading the whole history. The paper says it is the most accurate of the systems compared on four of five question-answering benchmarks, at 91.4% on LoCoMo and 72.6% on LongMemEval-S, 14.3 points above the strongest baseline there.

Why it's worth knowing: Memory that grows with every turn eventually dominates the prompt. A capped lookup is what keeps a long-running agent fast.

https://huggingface.co/papers/2611.12068
