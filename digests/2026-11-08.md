### The end of Microsoft Research's AI Frontiers group

Hacker News

In a post on hunch.net, the author says Microsoft Research's AI Frontiers group, formed after ChatGPT so coordinated teams could work on agents and new training ideas, was moved into Microsoft AI in early September. He writes that former Inflection leaders there are committed to scaling, that this clashes with Frontiers' research program, and that the group was not wanted.

Why it's worth knowing: Frontiers was about 50 people, and its public work included the Autogen agent framework and attempts at new objectives such as a recursive Full Bandwidth Transformer. The post is a firsthand account of a research mandate disappearing inside a much larger product organization.

Terms:
- **AI Frontiers** — Microsoft Research AI Frontiers — A Microsoft Research sub-group of about 50 people, started in 2023 to run coordinated AI projects rather than isolated one-person efforts.
- **Autogen** — AutoGen — An open-source framework from that group for orchestrating multiple AI agents so they can divide a task.

### Claude Code's "Don't Ask Again" exposes passwords in 1,122 public GitHub files

Hacker News

Apiiro reports that Claude Code's "Don't Ask Again" option is linked to passwords and other secrets in 1,122 public GitHub files. On Hacker News, readers argued over whether skipping per-command review has become normal for agentic coding, and over how much of that risk a sandbox can contain.

Why it's worth knowing: A convenience toggle on a widely used coding agent is showing up as leaked credentials in public repositories. For anyone running an agent against a real repo, the approval step is part of the security boundary.

Terms:
- **Don't Ask Again** — Claude Code permission memory — A Claude Code option that stops prompting for approval of a command the user has already allowed, so later commands of that kind run without a fresh review.

### Goodbye Claude, Hello Pi

### TokiRecur – llama.cpp LLM launcher with KV-cache recycling

Hacker News (watchlist)

TokiRecur sits in front of llama-server and, on an exact token-for-token prefix match, reuses that prompt's KV cache instead of running prefill again. The project reports 62–96 percent faster time to first token across nine workloads, says the cache is memory-only after disk restore corrupted outputs, and notes that one changed token forces everything after it to be recomputed.

Why it's worth knowing: Local servers often pay a full prefill cost for a long system prompt that did not change. The speedup holds only while that prefix stays identical, so two harnesses with different system prompts still start cold.

Terms:
- **KV cache** — key-value cache — The stored attention state for tokens the model has already processed. Reusing it skips recomputing that prefix.

https://github.com/lhadzic377-netizen/TokiRecur

### Opus 5.5 wrote its own quantiser for Qwen3.5-0.8B, no llama-quantize, no imatrix. 5.9× better than Unsloth's same-size file.

r/LocalLLM

A LocalLLM post says Claude Opus 5.5 wrote a NumPy quantizer for Qwen3.5-0.8B with no llama-quantize tool and no importance matrix, then assigned IQ4_XS, Q5_K, and Q6_K by measuring which tables rounding hurt. Against BF16 on llama.cpp b11928, the author reports KL divergence of 0.0157 for a 498.5 MB file, versus 0.0925 for an Unsloth file of similar size.

Why it's worth knowing: The useful part is the measurement loop: spend bits where the activations are sensitive, then publish the distance from the float model. The author's figure of about 5.9 times lower divergence is that one comparison, on one 0.8B model.

Terms:
- **KL divergence** — Kullback-Leibler divergence — A score of how far the quantized model's next-token probabilities sit from the full-precision model. Lower means a closer match.
- **imatrix** — importance matrix — A llama.cpp calibration file that records which weights matter more so quantization can protect them. This experiment was not allowed to use one.

https://www.reddit.com/r/LocalLLM/comments/1xq889l/opus_55_wrote_its_own_quantiser_for_qwen3508b_no/

### Strata-like speed, but one engine for any MoE at any quant, with an automatic planner: phones, laptops, consumer and data-center GPUs

r/LocalLLM

BigMoeOnEdge, built on llama.cpp, streams mixture-of-experts weights from flash so a model larger than RAM can run, and it picks settings by measuring the machine at load. The author reports a 22 GB Qwen3.6-35B-A3B Q4_K_M on a 16 GB laptop finishing a long coding prompt at about 350 tokens per second of prefill on the GPU and about 14 tokens per second of decode on the CPU.

Why it's worth knowing: Expert weights are most of a mixture-of-experts model's size. Streaming them is what puts a 22 GB model on a 16 GB laptop, at a decode rate suited to an agent that can wait.

Terms:
- **MoE** — mixture of experts — A model that stores many specialist sub-networks and activates only a few for each token, so it is large on disk and cheaper per token than a dense model of the same total size.

https://www.reddit.com/r/LocalLLM/comments/1xqgsjq/stratalike_speed_but_one_engine_for_any_moe_at/

### Show HN: An immutable local inference appliance with routing capability

Hacker News (watchlist)

Sibyl is a pre-alpha inference appliance that installs a signed Fedora image and serves GGUF models through llama.cpp, with OpenAI, Anthropic, and Ollama-compatible APIs. A router can send each request to a local model or a cloud provider under rules the operator sets, including one that keeps any request containing a secret on the machine; the author says only the AMD gfx1100 target has been tested on hardware.

Why it's worth knowing: It packs model swapping, per-program API keys, and a TPM-unlocked encrypted disk into one host image that can roll back. The rule that secrets stay on the box is the design worth copying while the ISO is still pre-alpha.

https://github.com/diffsec/sibyl

### Canada's military is using Palantir software. What are the risks?

CBC News

CBC News reported on November 7 that National Defence has used Palantir's Gotham software since 2020, under a contract first valued at $14 million and potentially worth up to $63 million that was marked internally as not for public disclosure. The department says the system runs on closed networks in Canada and that government data under the contracts stays in the country; researchers quoted by CBC warn that US law can still reach records a US company possesses.

Why it's worth knowing: The question is whether a classified analytics system hosted in Canada is still exposed because the vendor is American, and whether the Forces could replace the software if they needed to. DND's assurance and that legal concern are both part of the story.

Terms:
- **Gotham** — Palantir Gotham — Palantir software that pulls together records from separate databases. DND told CBC it is used on closed, classified networks inside Canada.
- **DND** — Department of National Defence — The federal department responsible for the Canadian Armed Forces, and the department that holds these contracts.

https://www.cbc.ca/news/politics/palantir-canadian-military-9.7409099
