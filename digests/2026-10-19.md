### Hybrid Reasoning Agents: LLM agents that think in latent space, act through text

Hacker News

The Hybrid Reasoning Agents paper has an agent switch between thinking in latent space (internal vectors) and acting through text, so tools still work. Across 11 benchmarks it reports 10.4% better performance, 35.5%-54.7% fewer tokens and 1.8x-2.6x faster inference.

Why it's worth knowing: Commenters note the trade-off: latent thoughts are harder to trace than written reasoning, though the paper claims they can be inspected directly.

Terms:
- **latent space** — Not an acronym. Technical term for a model's internal vector representation space — These are the continuous hidden vectors a neural network uses internally. Reasoning in latent space means passing these vectors along instead of writing out words, which can save tokens but is harder for humans to read.
- **tokens** — Not an acronym. The text units a language model reads and writes — A token is a word fragment or short piece of text. Inference cost and speed are usually measured in tokens.

https://arxiv.org/abs/2610.18861

### 2x Tesla p100s, q6_k quant, Qwen 3.8 27B ~60tps

Hacker News (watchlist)

A fork of llama.cpp tuned for two Tesla P100 GPUs runs Qwen3.8-27B decode at 1.86x upstream speed (17.5 to 32.6 tokens/s), and about 54 tokens/s using the model's built-in MTP head. It also fits the full 262k context window with vision loaded and reports slightly lower numerical error than upstream.

Why it's worth knowing: It shows that cheap, older datacenter GPUs can still run a 27B model at usable speed with targeted kernel work.

Terms:
- **llama.cpp** — Project name, not an acronym. The .cpp means it is written in C++ — An open-source engine for running LLMs locally on CPUs and GPUs. It uses quantized models in the GGUF format and offers a CLI and an OpenAI-compatible server.
- **MTP** — Multi-Token Prediction — A model head trained to predict several upcoming tokens at once. It can be used for speculative decoding, where guesses are verified in a batch to speed up generation.

https://github.com/Kmic-68/llama.cpp

### ggml-org/llama.cpp b11727

GitHub: ggml-org/llama.cpp

llama.cpp release b11727 fixes a bug where gguf-split and export-lora could silently write corrupted tensor output from a truncated GGUF file. They now reject short reads, and a regression test covers it.

Why it's worth knowing: Silent corruption of model files is hard to diagnose, so failing loudly is a real reliability gain.

Terms:
- **GGUF** — GPT-Generated Unified Format — A single-file model format used by llama.cpp that stores weights, often quantized, along with metadata.

https://github.com/ggml-org/llama.cpp/releases/tag/b11727
